# IA

## Rol de la IA
La IA no controla el flujo de compra ni toma decisiones transaccionales.

El objetivo del proyecto es reducir al maximo la necesidad de usar IA.

Su uso esta limitado a:
- FAQ.
- Explicacion de reglas.
- Explicacion de condiciones.
- Soporte conversacional acotado.
- Reformulacion de respuestas para lenguaje natural.

## Principio Operativo
- Primero responder con reglas fijas, FAQ curada o rutas deterministas.
- Solo usar IA cuando no exista una respuesta exacta predefinida en la base de conocimiento.
- Si una consulta puede resolverse con menu, plantilla o texto fijo, no se debe invocar IA.
- La IA debe ser el ultimo escalon antes de soporte humano, no el primero.

## Casos No Permitidos
- Confirmar pagos.
- Reservar numeros por interpretacion libre.
- Elegir numeros o modificar compras sin flujo determinista.
- Aprobar boletos o resolver disputas.
- Responder fuera del contenido autorizado del negocio.

## Politica de Respuesta
- Si la intencion del usuario coincide con una accion transaccional, manda el flujo estructurado.
- Si la pregunta coincide con una FAQ estructurada, responder sin IA usando contenido fijo o parametrizado.
- Si la pregunta es abierta pero respondible con base de conocimiento y no existe respuesta fija suficiente, responde IA.
- Si la confianza es baja o hay ambiguedad alta, derivar a menu o soporte humano.

## Jerarquia de Respuesta
1. Flujo transaccional determinista.
2. Respuesta fija del FAQ.
3. Respuesta parametrizada con datos del sistema.
4. IA acotada a base de conocimiento.
5. Soporte humano.

## Base de Conocimiento
Fuentes permitidas:
- Reglamento.
- Premios.
- Fechas.
- Metodos de pago.
- Condiciones.
- Preguntas frecuentes.

La FAQ operativa editable debe vivir en un catalogo administrable y versionado desde panel.

## Requisitos
- Las respuestas deben quedar acotadas al contenido autorizado.
- Debe ser posible versionar o actualizar la base de conocimiento.
- Debe existir logging de prompts y respuestas si el costo y privacidad lo permiten.
- Deben definirse limites de tono, longitud y seguridad.
- Debe existir una lista clara de intenciones que nunca pasan por IA.
- Debe existir un catalogo de FAQ y textos fijos publicado antes de habilitar IA para soporte abierto.
